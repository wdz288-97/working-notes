# Chinese writing guide for the zh/ pages

How the Chinese pages are written. Research notes on 刘润 and 数字生命卡兹克 (November 2026) first, then the site's own rules, which win where they differ.


用途：把个人网站从英文改写成自然的大陆中文。参照：数字生命卡兹克、刘润（2026年9–11月文章，来源见文末）。

**一句话定调：用刘润的骨架，说卡兹克的人话。** 刘润给结构：短句、自问自答、一节一个判断。卡兹克给口吻：第一人称，讲自己到底怎么干，术语先“翻译成人话”。两人的粗口、“。。。”、文末广告和标题党不学。

## 1. How they write 他们怎么写

| | 卡兹克 | 刘润 |
|---|---|---|
| 句子 | 口语流水句，逗号一路串下去；长句后面跟一句极短的话收住：「一声长叹。」「但现在，也没了。」 | 短句，常被逗号切成几截：「嫌贵，退订不就好了？」「说干就干。」 |
| 段落 | 基本一句一段 | 一到三句一段，关键句加粗、单独成段 |
| 开篇 | 时间+事件：「昨天晚上，Anthropic终于公开了他们的IPO申请」，接自己的反应，再说「一个一个说。」 | 讲一个人的事：「上个月，美国有个程序员，干了件很疯狂的事。」或直接问读者；几段内亮出加粗论点 |
| 小节开头 | 「先说最核心的这个」「惯例先总结一下基本信息。」 | 直接点题：「第一样东西，开源。」紧跟一句定义 |
| 称呼 | 我 + 大家（“给大家分享一下”）+ 你（“你会发现”） | 你为主，我表态（“我想”“在我看来”） |
| 引入概念 | 「CI这个词，可能很多不写代码的朋友没怎么听过，大概意思就是」「翻译成人话就是」 | 「什么叫X？就是…」「我把它叫做：按需式学习。」再配类比（奶茶店、织布机） |
| 连接词 | 其实、然后、所以、而且、比如、甚至 | 可是、但、所以、那、这时候、比如/再比如、你想想 |
| 推进方式 | 按时间线或流程：「顺着流程，我们一个一个模块说。」 | 自问自答：「为什么？」「那问题来了。」 |
| 正式度 | 很口语，带网络词（魔幻、上头） | 口语但干净 |
| 数字 | 阿拉伯数字，精确到个位（“审了298个合并请求”）；用对比让数字有感觉（“连10秒都买不起”） | 少而准；外币括号换算（“约1900元人民币”）；递进排列（“95%、98%、99%”） |
| 收尾 | 「写在最后」，回到个人感受 | 「最后的话」「好。简单做个总结。」回到开头的问题，用一句对仗金句收 |

原句（摘自所读文章）：

- 卡兹克：「这个特质，其实也叫：」换行「领导力。」（冒号断行，制造停顿）
- 卡兹克：「你看，皇帝的注意力，跟我们普通人的，其实也差不了多少。」
- 卡兹克：「这个可能稍微有点绕，我用人话解释一下。」
- 刘润：「做出一款软件，和做好一款软件，是两码事。」
- 刘润：「什么叫归因能力？就是面对一个结果，你能不能找准它真正的原因。」
- 刘润：「问题知道了，那，怎么办？」

两人的共同点，最值得学：先讲具体的事，再给结论；新概念先说它干什么用；一节只讲一个点。

## 2. Translationese 欧化中文：病和改法

| 病 | 例 | 改法 |
|---|---|---|
| 照搬 a/an | 我是一名分析师 | 删“一名/一个”，或说“做…的” |
| 无生命主语 | 这个网站记下… | 让人当主语，或用“这里…” |
| 长定语 | 要据此行动的人 | 拆短：拍板的人、动手的人 |
| 虚动词+名词 | 进行分析、实现提升 | 分析、提高 |
| 介词开头 | 关于这个问题，对于业务方来说 | 直接说事 |
| 连接词太满 | 因此、然而、此外，句句都有 | 靠语序衔接，能删就删 |
| 英式比喻直译 | 缺口（gap）、旅程、赋能 | 坎、差距；说具体动作 |
| 歧义切分 | 回答对的问题 | 换说法 |

### 六个原句改写

**1.**「我是定泽，一名商业智能分析师。」
→ **我叫定泽，是做BI（商业智能）分析的。**
“一名…师”是 a 的直译，像简历。中文介绍自己，习惯说“做什么的”。

**2.**「这个网站记下我实际是怎么做这些工作的。」
→ **这个网站，记的是我平时到底怎么干这份活。**
“实际是怎么…的”是 actually 的硬译；用“到底”带出语气，“这份活”接住上一句。

**3.**「它还没写完，也没打算写完。我的做法在变，我就接着补充和修改。」
→ **这里不会有“写完”的一天。我的做法一直在变，它也跟着改。**
“没打算写完”是 isn't meant to be 的直译；“补充和修改”两个书面词并列，“跟着改”就够了。

**4.**「你和有用的结果之间，隔着两道缺口」
→ 标题：**拿到结果，离能用还差两道坎**
“缺口”是 gap 的直译，中文说“坎”。正文可以先用刘润式短句拉开反差：“拿到结果，不等于能用。”

**5.**「判断结果有没有回答对的问题」
→ **判断结果是不是答非所问**；要强调“问题本身问对没有”时写：**看它答的，是不是真正该问的那个问题。**
原句能读成“回答对/的问题”，有歧义。“答非所问”是现成的说法。

**6.**「分析结论就是靠这一部分，才送到要据此行动的人手里。」
→ **这是闭环的后半段：把结论送到拍板、动手的人手里。**
更口语的版本：**分析做得再好，到不了拍板的人手里，也落不了地。后半段干的就是这件事。**
“据此”是公文腔；“要据此行动的人”是长定语，拆成“拍板、动手的人”。

## 5. Checklist 逐行检查清单

1. 一句超过25个字，就找逗号断开，或拆成两句。
2. 一段最多三句；关键判断单独成段。
3. 删掉“一个、一名、一种”，除非在强调数量。
4. 一句里“的”超过两个，就改写定语。
5. “进行、作出、加以、实现”加名词，换成直接的动词。
6. 句首的“关于、对于、随着、在…方面”，删掉，直接说事。
7. 主语是“网站、数据、本文、它”时，试试换成“我”“你”，或干脆不要主语。
8. “因此、然而、此外、同时”一段最多一个；能换成“所以、但、还有”就换。
9. “被”字只留在真有吃亏意味的地方。
10. 每节第一句就点题（“先说…”“第一件事，…”），不铺垫。
11. 新概念先说它干什么用，再给名字：“什么叫X？就是…”。
12. 每个抽象说法后面，跟一个例子或数字（“比如…”）。
13. 自问自答（“为什么？”“那怎么办？”）一页不超过三次。
14. 对仗金句只放在全文结尾或少数小节结尾，不要节节都有。
15. “我”讲经历，“你”讲读者能做的事；不用“笔者”“读者朋友们”。
16. 数字用阿拉伯数字，大数用“万、亿”；给一个对比，让数字有感觉。
17. 术语按第3、4节写，同一篇里写法统一。
18. 中文和英文字母、数字之间加半角空格（「近 7 年」「AI 聊天工具」），和简历、面试幻灯片一致。两位作者不加，本站统一加。
19. 标点用全角；引号用“”；少用破折号和分号；不用“。。。”和“～”。
20. 删英式套话：值得注意的是、总的来说、在当今时代、赋能、旅程。
21. 念出来：像说明书或新闻稿的句子，重写。
22. 改完对照英文原文：事实、数字、限定词（“大部分”“目前”）一个不能丢。

# Site rules (these win)

## Constraints

- **Block structure must match the English exactly**: the same `<p>`, `<li>`, `<h1>`–`<h4>`, `<dt>`, `<dd>`, `<td>`, `<th>`, `<figcaption>`, `<aside>`, `<section>`, `<article>`, `<figure>`, `<table>`, `<blockquote>` elements in the same order. You can't split or merge paragraphs; shorten sentences inside them instead. Same ids, classes, data-* attributes, SVG geometry. Inline tags (`<strong>`, `<mark>`, `<a>`, `<b>`, `<i>`) can move to wrap the matching Chinese words.
- After writing, run `python -I tools/check-translations.py` from the repo (`C:\Users\wdz28\my_project\working-notes`). Your pages must print OK. Fix until they do.
- Keep a half-width space between Chinese and Latin letters or digits (「近 7 年」「AI 聊天工具」). This is the site's existing convention and matches the owner's approved deck; it overrides rule 18 of the style guide.
- Don't use 闭环, 赋能, 抓手, 底层逻辑 (except as the book title), 值得注意的是, 综上所述, 首先…其次…最后, 不仅…更是, em dashes, or piles of ；. Use 复盘 at most once per page.
- SVG labels: keep each label about as long as the current Chinese one or shorter; they must fit their boxes.
- Footer: 「作者：黄定泽。联系方式：<a…>dzwong97@gmail.com</a>，或 <a…>领英（LinkedIn）</a>。」 No English name.

# Editor review (second pass)

After writing or changing Chinese text, review it as a senior mainland editor who also reads English, with the English page side by side.

## Method, block by block

Put the English page and the Chinese page side by side and go block by block (each <p>, <li>, heading, table cell, caption, quiz option, SVG label, aria-label, alt). For each block ask:

1. **Meaning**: same facts, numbers, qualifiers (most, often, only, at the moment), same claim strength? Nothing added, nothing dropped? If not, fix the Chinese.
2. **Translationese (欧化)**: English skeleton showing through? Typical signs: 一名/一个 as articles; 实际是怎么…的; 据此; long 的-chains; 进行/实现/作出 + noun; sentences starting with 关于/对于/随着; abstract nouns as subjects (这个网站记下…); 被 without a reason; English-order lists. Rewrite the way a mainland writer would say it.
3. **Word choice and collocation**: would a mainland professional say it this way? (e.g. 缺口 for gap → 坎/差距; 回答对的问题 is ambiguous → 答非所问 or 该问的问题). Prefer common workplace words over literary or Taiwanese/Hong Kong usage.
4. **Terms**: exactly as in the fixed-terms table, consistent across your pages.
5. **Flow**: does the paragraph read smoothly in Chinese, with the point first? Split long sentences inside the block.

Don't polish what's already natural. Don't add slang, jokes, 金句 or rhetorical questions that aren't in the English.
