Using AI, chapter 4 of 6

Divide, delegate and reuse

About 7 minutes to read

Once you can brief and check AI's work, the next questions are which steps to hand over, how to pass work between AIs, and when a method is worth turning into something reusable.

Key ideas

  • Hand over the steps that need no important human judgement in between; keep a person where judgement matters.
  • Give each AI, tool or person the contribution it's best at, and give the reviewer the evidence as well as the conclusion.
  • Start with the simplest setup that works, and add an agent only when the next step depends on what it finds.
  • A handover carries the goal, decisions, evidence, current state and open questions.
  • Make a method reusable when its steps repeat and the setup and upkeep pay back, and give agents only the access the job needs.

Hand over the steps that need no judgement in between

Start by breaking the task into its steps, then ask of each one: does anything important need a person's judgement between this step and the next? Steps that can be done by code or by an agent using a computer, with no such judgement in between, are good candidates to hand over. Steps where a wrong turn is costly, or where the right answer depends on context only you have, stay with you or get a review point.

If the task is new to you, you don't have to work out the split alone. Look at how other people use AI for the same kind of task, try it, and build your own experience over time. The checkpoints from chapter 3 still apply to anything you hand over.

In my practice

Steps that can be automated by code or computer use, without important human judgement in between, can be done by AI. When I'm new to a kind of task, I first research how other people do it with AI, and gather experience as I go.

Give each helper the contribution it's best at

Once AI is a collaborator, using more than one becomes natural. One may be good at finding sources, another at working inside a software project's code, another at explaining. Treat these as assignments to test: products change, and so does what each is best at. My own current choices are on the Using AI page, with a date.

The helper doesn't have to be an AI. A calculator is a better colleague for arithmetic than another language model, and a specialist can be the right reviewer even when AI wrote most of the draft. The question to ask is which contribution the task needs, and which setup can provide it at an acceptable cost. The smallest team that can produce and justify the result is usually the right one.

Whoever reviews the work should get the task and the evidence, as well as the draft's conclusion. A reviewer who sees only a polished answer tends to inherit its assumptions.

Start simple, and add an agent only when steps vary

More helpers mean more coordination. Anthropic's guidance on building agents recommends starting with the simplest solution and adding complexity only when it improves the result.1 It separates two shapes:

  • A workflow follows a fixed sequence of steps that you design in advance.
  • An agent chooses its next step based on what it finds, which helps when the path can't be known in advance.

You can coordinate useful work by hand before automating any of it. Moving a carefully prepared brief between two tools is already a workflow. Automating a process you don't yet understand only repeats its mistakes faster.

A handover carries the goal, the evidence and the state

When work moves between AIs or chats, keep one clear lead who brings the results together and checks them. Then pass on enough for the next helper to continue without guessing:

  • the original goal, and the decisions already made;
  • the evidence gathered so far, and where it came from;
  • the current state of the work, and the useful files;
  • the questions still open.

Passing on only a polished conclusion invites the next helper to build on assumptions nobody checked. Keep the coordination and the final review in proportion to the task: a two-step job doesn't need a project plan.

In my practice

Without a ready-made workflow for coordinating agents, I don't do this often. When I do, a handoff skill (Matt Pocock's is a good one) passes the work to another agent cleanly. Simpler ways are to have the main agent start a helper agent of its own (a sub-agent), or to give the agent the name or ID of an earlier chat in the same project. I expect that last one to use more tokens, though I haven't measured it.

Decide what's worth making reusable

When a task keeps coming back, you can keep using a prompt, write a skill, write a script, set up an agent workflow, or combine them. Three questions decide it: which steps repeat, where judgement is needed, and whether the setup and upkeep are worth the benefit.

A skill packages instructions and resources that an agent loads when they're relevant,2 so it suits a method that repeats but still needs judgement on each run. A script suits steps that run the same way every time. Saving an untested method as a skill keeps its mistakes along with its convenience, so test it on real work first (chapter 5).

Set up the project so an agent can work well

An agent works better in a project built for it, in the same way a new colleague does better with a good handover pack. I've adopted five practical principles, as flexible guidance rather than strict rules:

  1. Keep changes understandable and contained. Coherent modules with clear inputs, outputs and constraints, adding structure only where it helps.
  2. Provide a short map to what matters. Point to the relevant project knowledge, definitions, decisions, setup steps and specialist guidance, rather than one huge instruction file.3
  3. Make important requirements checkable. Tests and checks with failure messages that say what to fix, and written commands for setup and verification. Instructions alone don't guarantee an agent follows them.4
  4. Give the agent tools to verify the actual result. A browser, or computer use (operating the screen, mouse and keyboard), for visual work and for operations it must perform, as chapter 3 describes.5
  5. Keep meaningful human review. Including the fixed checkpoints in analysis: validating the raw output, and reviewing the final interpretation.

Good engineering habits help agents for the same reasons they help people. I usually pick engineering skills that teach agents these habits from popular, well-known sources, then test them on my own work.

Give an agent the access its job needs

Advice can be reviewed before you use it. An action may already have changed a file, sent a message or exposed information. As an agent's ability to act grows, the need for clear limits grows with it.

  • Keep permissions in proportion to the job. Work on safe copies where you can, and keep approval for consequential steps such as sending, deleting or paying.
  • A written instruction isn't a lock. "Don't send anything" in a prompt doesn't technically stop an agent that has permission to send.
  • Know where your data goes. Running an agent on your own computer doesn't mean your data stays there: the model service or a connected tool may run elsewhere.6
  • Text in a page isn't an instruction. A web page or document can contain words aimed at the agent. Finding them doesn't give them authority over your task.6

Common trap: full access to save time

Giving an agent every permission avoids interruptions, until it acts on a misunderstanding. Grant what the task needs, and widen access step by step as the agent proves itself on that kind of work.

Check your understanding

You run the same monthly data export, with exactly the same steps, every time. What fits best?

A script. The steps repeat and don't vary, and no judgement is needed between them, so the setup pays back quickly.

You pass work to a second AI with just the finished draft. What's missing?

The goal, the decisions already made, the evidence and where it came from, the current state, and the open questions. Without them, the second AI builds on assumptions nobody checked.

Your prompt tells an agent "don't email anyone", and it has access to your email. Is that safe?

No. An instruction isn't a technical barrier. If the task doesn't need email, don't give the agent email access; if it does, keep sending behind your approval.
